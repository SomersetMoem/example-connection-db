# JDBC (Java Database Connectivity)

## Введение

JDBC API — это мост между Java-приложениями (включая автотесты) и базой данных. Взаимодействие из Java-кода с базой данных происходит через стандартизированный Java API.

**Ключевые особенности:**

- API JDBC одинаковое для любой базы данных (единый интерфейс)
- Соединение с базой данных осуществляется по протоколу TCP/IP
- Каждый SQL-запрос автоматически оборачивается в транзакцию

## Транзакции и принципы ACID

**Пример задачи:** Перевод 50 рублей с аккаунта Васи на аккаунт Пети.

В обычном Java-коде это сложно сделать безопасно, так как нет встроенного механизма транзакций. После выполнения операции "списать 50 рублей у Васи" может возникнуть исключение, и операция "зачислить 50 рублей Пете" не выполнится.

В базах данных есть транзакции, которые должны соответствовать принципам **ACID**:

### A — Атомарность (Atomicity)
Либо все операции в транзакции выполняются успешно, либо ни одна из них. В нашем примере: либо деньги и списываются у Васи, и зачисляются Пете, либо остается все как было.

### C — Согласованность (Consistency)
Выполненные действия не должны приводить к переходу системы в непредусмотренное состояние. Например, баланс аккаунта не может быть отрицательным. Если такое нарушение произойдет, транзакция отменяется.

### I — Изоляция (Isolation)
Никакие внешние (параллельные) попытки изменить данные во время выполнения транзакции не должны допускаться. Если у Васи списываются 50 рублей, то во время этой операции никто другой не должен иметь возможность изменить его баланс.

### D — Долговечность (Durability)
Если получен ответ о том, что транзакция выполнена успешно, то изменения гарантированно сохранены и не будут потеряны даже при сбое системы.

## Основные компоненты JDBC

### 1. Class DriverManager

**Назначение:** Класс для работы с различными драйверами базы данных.

**Особенности:**
- Для каждой БД используется свой специфический драйвер
- В DriverManager регистрируются все драйверы, используемые в проекте
- По JDBC URL драйвер-менеджер находит соответствующую реализацию и возвращает подходящий Connection

**Структура JDBC URL:**
```
jdbc:<подпротокол>://<хост>:<порт>/<база_данных>
```

**Пример использования:**
```
String url = "jdbc:mysql://localhost:3306/testdb";
Connection conn = DriverManager.getConnection(url, username, password);
```

> ⚠️ **Важно:** Этот класс считается устаревшим. В современных проектах рекомендуется использовать DataSource.

### 2. Interface DataSource

**Назначение:** Современный интерфейс для получения Connection.

**Особенности:**
- Создается как объект для конкретной БД
- Не содержит фабрику разных драйверов (в отличие от DriverManager)
- Поддерживает расширенные возможности конфигурации

**Пример создания:**
```
HikariDataSource dataSource = new HikariDataSource();
dataSource.setJdbcUrl("jdbc:mysql://localhost:3306/testdb");
dataSource.setUsername("user");
dataSource.setPassword("password");

Connection conn = dataSource.getConnection();
```

**Основное преимущество:** **Connection Pool** — при каждом запросе соединения не создается новое, а возвращается уже созданное ранее из пула. Это значительно экономит ресурсы системы и улучшает производительность.

### 3. Interface Connection

**Назначение:** Абстракция над TCP/IP соединением с базой данных.

**Ключевые характеристики:**
- **Thread-unsafe:** одно соединение не должно использоваться несколькими потоками одновременно
- **Обязательно должен быть закрыт** после использования (implements AutoCloseable)
- **Управляет транзакциями** (commit, rollback, autocommit)
- **Создает Statement** для выполнения SQL-запросов

### 4. Interface Statement

**Назначение:** Абстракция над SQL-запросом, создается из Connection.

#### Виды Statement:

##### Statement (базовый)
**Не рекомендуется к использованию в production**

- ✅ **Плюсы:** Легко логировать и отлаживать
- ❌ **Минусы:** Медленное выполнение и уязвимость к SQL-инъекциям

##### PreparedStatement (рекомендуемый)
**Наследник Statement**

- SQL-запрос компилируется и парсится в момент создания, а не в момент выполнения
- ✅ **Плюсы:** Высокая скорость выполнения, полная защита от SQL-инъекций
- ❌ **Минусы:** Более сложное логирование из-за параметризации

**Пример:**
```
PreparedStatement ps = connection.prepareStatement("SELECT * FROM users WHERE id = ?");
ps.setInt(1, userId);
```

##### CallableStatement
**Специализированный Statement для вызова хранимых процедур**

- Используется для выполнения stored procedures
- Поддерживает входящие и исходящие параметры

> 📝 **Примечание:** Все виды Statement реализуют интерфейс AutoCloseable, поэтому должны быть закрыты после использования.

### 5. Interface ResultSet

**Назначение:** Абстракция над результатами выполнения SELECT-запроса.

**Особенности поведения:**
- Ведет себя как итератор (cursor-based)
- Содержит метод `next()` для перехода к следующей записи
- `next()` возвращает `true`, если есть следующая строка; `false`, если данных больше нет
- **Ленивая загрузка:** держит соединение с БД и подгружает данные при необходимости
- `next()` не только возвращает boolean, но и перемещает внутренний курсор на следующую запись

**Пример использования:**
```
ResultSet rs = statement.executeQuery("SELECT name, age FROM users");
while (rs.next()) {
    String name = rs.getString("name");
    int age = rs.getInt("age");
    // обработка данных
}
```

### 6. Interface Driver

**Назначение:** Интерфейс для реализации специфических драйверов БД.

**Принцип работы:**
- Интерфейс определяет методы, которые должны быть реализованы производителем драйвера
- Конкретный драйвер подключается через зависимости проекта (например, MySQL Connector/J)
- Остальная логика JDBC уже реализована в стандартной библиотеке Java

## Архитектура взаимодействия

```
Java-приложение → JDBC API → Database Driver → TCP/IP → База данных
```

## Пример полного цикла работы

```
// 1. Создание DataSource
HikariDataSource dataSource = new HikariDataSource();
dataSource.setJdbcUrl("jdbc:postgresql://localhost:5432/mydb");
dataSource.setUsername("user");
dataSource.setPassword("password");

// 2. Получение Connection
try (Connection connection = dataSource.getConnection()) {
    
    // 3. Создание PreparedStatement
    try (PreparedStatement ps = connection.prepareStatement(
            "SELECT name, email FROM users WHERE age > ?")) {
        
        // 4. Установка параметров
        ps.setInt(1, 18);
        
        // 5. Выполнение запроса и получение ResultSet
        try (ResultSet rs = ps.executeQuery()) {
            
            // 6. Обработка результатов
            while (rs.next()) {
                String name = rs.getString("name");
                String email = rs.getString("email");
                System.out.println("User: " + name + ", Email: " + email);
            }
        }
    }
} catch (SQLException e) {
    e.printStackTrace();
}
```

## Лучшие практики

1. **Всегда используйте try-with-resources** для автоматического закрытия ресурсов
2. **Предпочитайте PreparedStatement** обычному Statement
3. **Используйте Connection Pool** (DataSource вместо DriverManager)
4. **Правильно обрабатывайте исключения** SQLException
5. **Не держите соединения открытыми** дольше необходимого

Такая архитектура обеспечивает единообразный интерфейс для работы с любыми базами данных через стандартизированное JDBC API.
